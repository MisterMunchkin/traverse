# Traverse 0.12.0 — experimental release notes

For trusted local development on a personal computer, starting with synthetic
accounts and test data. This is an experimental package, not a validated stable
browser/native automation release.

## Included

- Reviewed Expo 57/Router 57 and bounded Next 16.0.x/16.4.x App Router extraction
  with React 19.2.x; graph staleness and explicit exact-code trust remain intact.
- Private user-state authority for custom-extractor approvals and saved driving
  sessions, reported foreign native application rejection and owned-process
  cancellation cleanup fixes.
- A downloadable npm TGZ usable as a project dev dependency or in a selected
  global prefix, with SHA-256 checksums and source-file identities.
- Static website downloads and GitHub release-asset automation. Candidate
  previews are labelled separately from tagged release bundles.

## Installation

Download the TGZ and adjacent `SHA256SUMS` from the same selected website build
or GitHub release. Stop if checksum verification fails:

```sh
shasum -a 256 --check SHA256SUMS &&
npm install --save-dev ./mistermunchkin-traverse-0.12.0.tgz &&
npx --no-install traverse --version
```

Node 22.11+ and npm are required. The complete contributor checks use pinned
Node 22.21.1 on macOS arm64. Managed tev1 setup is optional, macOS arm64 only,
and downloads several GB separately. No model weights are in this TGZ.

## Validation and limitations

Contributor checks exercise serial package regressions, the static website,
Expo typecheck/lint/snapshots/offline export and isolated installed-archive CLI
behavior. The release workflow runs them again and tests the exact attached
archive as a dev dependency. A workflow definition is not a completed hosted
release run; consult its actual result before calling those assets verified.

Live packaged browser/native task completion, durable effects and recording
playback remain pending. Local Ollama APIs are unauthenticated; browser driving
does not enforce an origin/document/frame boundary. Contributor Netlify CLI and
Expo sample dependency advisories remain open after triage. Read the
[security guidelines](../security.md) before trying the package with app data.

The npm registry package remains unpublished. Public GitHub release downloads
require a public repository; a preview's same-origin candidate download does
not require making the repository public. Checksum files detect byte mismatch,
not publisher identity or authenticity.
