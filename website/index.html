  2. 02

    Graph lifecycle
  3. 03

    The agent-device runner observes live controls. Local-first mode asks tev1 for routine choices and escalates uncertainty to Codex or Claude within configured run limits.

  4. 04

    Act & verify

    Recheck targets before dispatch, then test explicit UI expectations. Retain outcome and cleanup receipts. A timeout or an unobserved effect stays uncertain.

SUPPORTED EXTRACTION

Expo Router

Two static Expo 57 / Router 57 profiles: the bundled root-app reference and an extended profile covering app/, src/app/, aliases and supported static config.

The extended profile may require a generated, reviewed extractor. Dynamic routing configuration and other version/package-manager combinations are outside current support.

Exact profile conditions
OPTIONAL LOCAL MODEL

tev1, on your machine

Managed setup currently supports macOS arm64. It acquires pinned Ollama and tev1:4b-q8_0 assets, verifies integrity, and tests a constrained choice.

Several GB, once per machine. Graph extraction needs no model. Other operating systems and architectures are not established support.

VALIDATION PENDING

Next App Router & live QA

Bounded static Next 16.0.x/16.4.x with React 19.2.x extraction is also supported. The packaged runner uses agent-device. Runner and provider contracts have fixture coverage; packaged live browser/native tasks and real subscription inference remain unverified.

Other frameworks need their own compatibility rules, independent validators and fixtures. Generating an adapter alone does not establish support.

The checksum detects corrupted or mismatched bytes; it is not a publisher signature. Stop if verification fails. Node and npm are still required. You can instead install the downloaded archive into your selected npm global prefix with npm install --global ./@@ARCHIVE@@. Model weights are a separate optional download.

02 Initialize a supported app

Inside a supported app with locked dependencies installed:

npx --no-install traverse init --no-interactive
npx --no-install traverse doctor
npx --no-install traverse graph check
npx --no-install traverse graph watch

Use the bundled reference sample for a provider-free start. Other supported profiles may need provider-assisted adapter authoring and review. Watch stays running; stop it with Ctrl-C.

Try the included app. The Expo sample has four routes and a synthetic Save/Cancel workflow. Install its lockfile before initializing; it needs Node 22.13+.

Maintainer handbook
01 Add the optional local sidekick+

On macOS arm64, run traverse setup separately from project initialization. Expect several GB of pinned runtime/model assets in ~/.cache/wayfinder. The setup verifies an actual constrained choice before reporting readiness.

npx --no-install traverse setup --dry-run
npx --no-install traverse setup
npx --no-install traverse doctor --model

The model check explicitly starts inference in an owned runtime. Graph commands need no model. Preserve failed setup receipts; do not overwrite conflicting caches.

Model setup and cache ownership
02 Configure the QA workflow+

Rerun traverse init interactively to select Codex or Claude, model, effort, policy and run limits. Install and sign in to the selected subscription CLI separately. Install agent-device separately for live UI driving and check its own runtime requirements.

For a bounded run, provide an explicit task file with observable expectations, a fresh session name and your actual app URL or device/app identifier. Local-first needs the verified model cache. Frontier mode sends every choice to your selected provider.

Without a configured frontier, escalation saves a brief and closes the session. That handoff is not a resumable paused run. Packaged live driving remains pending validation.

Task files, targets and bounded driving
03 Resolve a stale or unsupported graph+
traverse doctor --json
traverse graph check --json

Read the named failure receipts first. For supported source edits, use traverse graph refresh or watch with the accepted extractor. Framework/configuration changes may need compatibility review; changed extractor bytes require renewed exact-code trust.

For an unsupported profile, check the documented versions, route roots and static config conditions. Do not edit hashes or accept generated code just to make a check pass. Unknown frameworks require independent profile support.

Review, pinning and reacceptance
04 Keep project state portable+

Commit .wayfinder/project.json, extractor/artifact.json, graph.json and optional settings.json and shared guidance. Init supplies the ignore rules. Local execution trust, sessions and recordings remain ignored.

On a new machine, run init to review a pinned custom extractor again. It can reuse the exact artifact without generating it again. Local logs can include real UI text and input values; preserve them privately.

Project settings and agent integration
05 Understand what has been measured+

A small browser-fixture study compared Sol 6.1 at medium effort alone and with tev1 across 48 attempts, including failures. It is not a production benchmark or native-app guarantee. Other experiments found regressions and unsafe high-confidence choices.

Startup time, missing cost measurements and large frontier context limit interpretation. Packaged integration, durable effects and recording playback require separate observed validation.

Security guidelines

Use trusted local projects on a trusted personal computer with synthetic accounts and test data. Local Ollama access is unauthenticated. Browser driving does not enforce a website or frame boundary. Selected tools have your OS authority; frontier escalation and saved receipts may contain task or UI data.

Read the full security guidelines. Live packaged browser/native tasks and recording playback still need end-to-end validation.
